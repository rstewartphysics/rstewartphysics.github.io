Coding the Elegoo Uno R3 with Duino.app — Student Guide

Level: S4–S6 · Equipment: Elegoo Uno R3, breadboard, LEDs, buzzers, resistors, connecting leads (jumper wires), USB cable

This is your step-by-step guide for your first time writing code for the Elegoo Uno R3. Read each section in order. Do not skip the breadboard wiring — getting the wiring right is half the job.

1. What you need

  • [ ] Elegoo Uno R3 board
  • [ ] USB cable (the one that came in the kit)
  • [ ] A laptop/PC running Google Chrome
  • [ ] Breadboard
  • [ ] LEDs (the long leg is +, the short leg is −)
  • [ ] Resistors (you will use a 220 Ω resistor with each LED)
  • [ ] Active buzzer
  • [ ] Connecting leads (jumper wires)

⚠️ Never connect an LED directly to a pin without a resistor. Too much current will burn out the LED (and possibly the pin).

2. Open Duino.app in Chrome

Duino.app only works in Google Chrome (or another Chrome-based browser like Edge). It will not work in Safari or Firefox, because they cannot talk to the USB port.

  1. Open Google Chrome.
  2. In the address bar type: duino.app and press Enter.
  3. Plug your Elegoo Uno R3 into the laptop using the USB cable. A small light on the board should turn on.

3. Select the correct board (Arduino Uno)

The Elegoo Uno R3 is a copy of the Arduino Uno, so we tell Duino.app it is an Arduino Uno.

  1. Look for the board selector (usually near the top of the screen, may say "Select Board").
  2. Choose Arduino Uno.
  3. When you first upload, Chrome will pop up a window asking which USB device to connect to. Pick the one that mentions Arduino / CH340 / USB Serial and click Connect.

🔁 Every lesson: check the board still says Arduino Uno before you upload. If the wrong board is selected, your upload will fail.

4. How to write a new program

  1. Click the Code tab (this is where the program lives).
  2. You will see some default code already in the editor.
  3. Select all of it and delete it (click in the code, press Ctrl+A then Delete — on a Mac use Cmd+A then Delete).
  4. Type or paste in the new code from one of the samples below.

Every Arduino program has the same two parts:

void setup() {
  // runs ONCE when the board powers on. Set things up here.
}

void loop() {
  // runs OVER AND OVER, forever. Your main actions go here.
}
  • setup() runs one time at the start.
  • loop() runs again and again until you unplug the board.

5. Code vs // notes (comments)

Look carefully at these two lines:

digitalWrite(13, HIGH);   // turn the LED on
  • digitalWrite(13, HIGH); is code. The board reads it and does something. It must be spelled and punctuated exactly right (note the semicolon ; at the end).
  • Everything after // is a comment / note. The board completely ignores it. It is there for humans to read, to explain what the code does.

Two ways to write notes:

// This is a single-line note. Everything after the // is ignored.

/* This is a
   multi-line note.
   The board ignores all of it. */

✅ Why comments matter: good notes make your code easy to understand later and help you (and your teacher) find mistakes. You should add your own // notes to explain your thinking.

Rule of thumb: if you delete the code, the board stops working. If you delete the // notes, the board works exactly the same — you have just lost the explanation.

6. The golden rule: Compile BEFORE you Upload

Always Compile (check) first, then Upload (run).

  • Compile / Verify = the computer checks your code for spelling and grammar mistakes without sending it to the board. Nothing happens on the board yet.
  • Upload = the code is sent to the board and starts running.

Do this every single time:

  1. Click Compile (sometimes shown as a ✓ tick or "Verify").
  2. Read the message at the bottom. - If it says success / done compiling → carry on. - If it shows an error (usually red) → fix the mistake before uploading. The error message tells you the line number to look at.
  3. Only when it compiles cleanly, click Upload.

❌ Never upload code that has not compiled successfully. You will just upload broken code.

7. Understanding the breadboard

A breadboard lets you build circuits without soldering. You push component legs and wires into the holes, and the holes are secretly joined together inside.

How the holes connect (this is the important bit):

        a b c d e        f g h i j
   +  -  . . . . .  gap  . . . . .  +  -
 1 │  │  o o o o o       o o o o o  │  │
 2 │  │  o o o o o       o o o o o  │  │
 3 │  │  o o o o o       o o o o o  │  │
   ...
   ↑  ↑  └──┬──┘         └──┬──┘    ↑  ↑
  RED BLUE  joined in       joined  RED BLUE
  power     a row (a-e)     (f-j)   power
  rails
  • Power rails (the long lines down the two edges, marked + red and − blue): every hole in one rail is joined all the way down. We use these for power (+5V) and ground (−/GND).
  • Main holes (rows 1, 2, 3 …): each row is split into two halves by the centre gap.
  • In one half, the five holes a–e in the same numbered row are joined to each other.
  • The five holes f–j in that row are joined to each other.
  • The two halves are NOT joined across the centre gap.
  • Different numbered rows are not joined to each other.

So: to connect two things together, put their legs/wires in holes of the same row, on the same side of the gap.

Setting up power (do this for every circuit):

  1. Jumper wire from the Uno's 5V pin → the red (+) rail.
  2. Jumper wire from one of the Uno's GND pins → the blue (−) rail.

Now the whole red rail is +5V and the whole blue rail is ground (0V).

8. Components and the resistor colour-code check

LED (Light Emitting Diode): - Long leg = positive (+, "anode") — this side goes towards the Arduino pin. - Short leg = negative (−, "cathode") — this side goes towards GND. There is also a flat edge on the short-leg side. - An LED only works one way round. If it doesn't light, try turning it around.

Resistor: - It does not have a + or − side — it can go either way round. - Its job is to limit the current so the LED isn't damaged. - We use 220 Ω with each LED.

Resistor 4-band colour-code check (to confirm you grabbed 220 Ω):

Read the bands from the end where they are grouped closest together.

Band Meaning For 220 Ω
Band 1 1st digit Red = 2
Band 2 2nd digit Red = 2
Band 3 multiplier (× zeros) Brown = ×10
Band 4 tolerance Gold = ±5% (or Silver ±10%)

So 220 Ω = Red, Red, Brown, Gold. (2, 2, then one zero → 220.)

Colour value reference (digits / multiplier):

Colour Digit Multiplier
Black 0 ×1
Brown 1 ×10
Red 2 ×100
Orange 3 ×1,000
Yellow 4 ×10,000
Green 5 ×100,000
Blue 6 ×1,000,000
Violet 7 —
Grey 8 —
White 9 —

Your resistors are already labelled, but use this table to double-check you have the right one before building.

Buzzer (active type): - Has a + marked on the top, with a longer leg for +. - The + leg goes to the Arduino pin; the other leg goes to GND.

Sample 1 — Blink one LED

Goal: make one LED turn on for 1 second, off for 1 second, forever.

Breadboard wiring

  1. Set up power rails (5V → red rail, GND → blue rail) as in Section 7.
  2. Push the LED into the board so its two legs are in two different rows (e.g. long leg in row 5, short leg in row 6). The legs must straddle the gap or sit in separate rows — never both legs in the same joined holes.
  3. Put one end of the 220 Ω resistor in the same row as the LED's short leg (row 6), and the other end into the blue (−) rail.
  4. Connect a jumper wire from Arduino pin 13 to the same row as the LED's long leg (row 5).
 Arduino pin 13 ──────┐
                      │ (jumper)
   row 5:  o o [LONG leg of LED]
                 LED
   row 6:  o o [SHORT leg]──[220Ω resistor]──→ blue (−) rail ── GND

Current path: pin 13 → LED long leg → through LED → short leg → resistor → GND. ✅

The code

// Sample 1 - Blink one LED
// The LED is connected to pin 13.

void setup() {
  pinMode(13, OUTPUT);     // tell the board pin 13 is an OUTPUT (we control it)
}

void loop() {
  digitalWrite(13, HIGH);  // turn the LED ON  (send 5V to pin 13)
  delay(1000);             // wait 1000 milliseconds = 1 second
  digitalWrite(13, LOW);   // turn the LED OFF (0V)
  delay(1000);             // wait 1 second
}

Run it

  1. Compile (check for errors). 2. If clean, Upload. 3. The LED should blink on/off every second.

Try changing: make delay(1000) into delay(200) — what happens? (Compile and upload again to find out.)

Sample 2 — Traffic lights (multiple LEDs)

Goal: red → red+amber → green → amber → repeat.

Breadboard wiring

You now wire three LEDs, each with its own 220 Ω resistor, exactly like Sample 1 but using three different pins.

LED Arduino pin Resistor To
Red pin 8 220 Ω GND rail
Amber/Yellow pin 9 220 Ω GND rail
Green pin 10 220 Ω GND rail

For each LED: 1. Long leg in its own row, connected by a jumper to its Arduino pin (8, 9 or 10). 2. Short leg in a row → 220 Ω resistor → blue (−) rail.

Keep the three LEDs spaced a few rows apart so the legs don't touch.

The code

// Sample 2 - Traffic lights
// Red = pin 8, Amber = pin 9, Green = pin 10

void setup() {
  pinMode(8, OUTPUT);   // red
  pinMode(9, OUTPUT);   // amber
  pinMode(10, OUTPUT);  // green
}

void loop() {
  // RED
  digitalWrite(8, HIGH);
  digitalWrite(9, LOW);
  digitalWrite(10, LOW);
  delay(3000);          // red for 3 seconds

  // RED + AMBER (get ready)
  digitalWrite(9, HIGH);
  delay(1000);

  // GREEN (go)
  digitalWrite(8, LOW);
  digitalWrite(9, LOW);
  digitalWrite(10, HIGH);
  delay(3000);

  // AMBER (slow down)
  digitalWrite(10, LOW);
  digitalWrite(9, HIGH);
  delay(1000);

  digitalWrite(9, LOW); // all off, then loop repeats
}

Run it

Compile → Upload. Watch the sequence repeat. If an LED never lights, check its long/short legs and that its resistor reaches the GND rail.

Sample 3 — Buzzer beep and tones

Goal: make the buzzer beep, then play a few different tones.

Breadboard wiring

  1. Power rails set up as before.
  2. Put the buzzer on the breadboard with each leg in a separate row.
  3. Jumper from Arduino pin 7 to the row with the buzzer's + leg.
  4. Jumper from the buzzer's other leg's row to the blue (−) GND rail.

A buzzer does not need a resistor. Make sure the + leg goes to pin 7.

 Arduino pin 7 ──── [+ leg] BUZZER [− leg] ──── GND rail

Code 3a — simple beep

// Sample 3a - Buzzer beep
// Buzzer + leg on pin 7

void setup() {
  pinMode(7, OUTPUT);
}

void loop() {
  digitalWrite(7, HIGH);  // buzzer ON
  delay(500);             // for half a second
  digitalWrite(7, LOW);   // buzzer OFF
  delay(500);             // silence for half a second
}

Code 3b — playing tones

tone() makes a pitch (frequency in Hertz). Higher number = higher note.

// Sample 3b - Play three tones
// Buzzer + leg on pin 7

void setup() {
  pinMode(7, OUTPUT);
}

void loop() {
  tone(7, 262);   // play note C (262 Hz)
  delay(400);
  tone(7, 330);   // play note E (330 Hz)
  delay(400);
  tone(7, 392);   // play note G (392 Hz)
  delay(400);
  noTone(7);      // stop the sound
  delay(1000);    // pause before repeating
}

ℹ️ Some buzzers in the kit are active (one fixed beep) and some are passive (can play tones). If tone() only clicks, you have an active buzzer — use Code 3a instead.

Run it

Compile → Upload. Listen. Change the frequency numbers to make your own tune.

Sample 4 — LED + buzzer alarm

Goal: an alarm that flashes an LED and sounds the buzzer at the same time.

Breadboard wiring

Combine Sample 1 and Sample 3 on the same breadboard:

Component Arduino pin Extra
LED (long leg) pin 13 short leg → 220 Ω → GND rail
Buzzer (+ leg) pin 7 other leg → GND rail

Both share the same GND (−) rail and the same 5V supply. That is the whole point of the power rails — many components can share them.

The code

// Sample 4 - LED + buzzer alarm
// LED on pin 13, buzzer + on pin 7

void setup() {
  pinMode(13, OUTPUT);  // LED
  pinMode(7, OUTPUT);   // buzzer
}

void loop() {
  // ALARM ON: light + sound together
  digitalWrite(13, HIGH);
  tone(7, 1000);        // 1000 Hz tone
  delay(300);

  // ALARM OFF: dark + silent together
  digitalWrite(13, LOW);
  noTone(7);
  delay(300);
}

Run it

Compile → Upload. The LED and buzzer should pulse together. Challenge: add a second LED of a different colour (pin 12, its own resistor) that flashes in the opposite pattern. Write // notes explaining each line you add.

13. Troubleshooting

Problem Check this
Upload fails / "no board" Is Arduino Uno selected? Is the USB plugged in? Did you click Connect in Chrome's pop-up?
Red error when compiling Read the message — it names the line number. Most often a missing semicolon ; or a misspelled word.
LED won't light Long leg towards the pin, short leg towards the resistor? Resistor reaching the GND rail? Try turning the LED around.
Nothing on the breadboard works Did you wire 5V → red rail and GND → blue rail? Are legs in the same row on the same side of the gap?
Buzzer only clicks with tone() It is an active buzzer — use the simple beep code (3a).
Code uploaded but board does nothing Did you actually Upload, or only Compile? Compile just checks; Upload runs it.

  1. Open Chrome → duino.app, plug in the board.
  2. Arduino Uno selected.
  3. Code tab → delete default → paste your code.
  4. Compile (check). Fix any errors.
  5. Upload (run).
  6. Resistor with every LED. Long leg = +.
